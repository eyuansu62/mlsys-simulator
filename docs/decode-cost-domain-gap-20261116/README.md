## 与 PR #9（runtime-cost 校准 v1.21）的关系：同症状、不同问题

PR #9（`runtime-cost-calibration-v121`，已合并）给 **Graph/MRv2/async/RocmAttentionImpl、ctx≈1024–1043**

  用 #9 机制查 ctx=257 会**强制**抛 `CALIBRATION_MISMATCH`（§1）。#9 的 9.72% 对本场景**不构成任何精度主张**。
- **模型内解释不同**：#9 的固定项与 attention 因子是域内经验估计；本分析进一步显示，短上下文的名义
  `linear` 项约占 88%，使所用模型的批大小响应较平。即使手工越过域门禁，C1 绝对缺口从 −32.4% 收窄到

- **证据角色不同**：#9 是已合并的域内 retrospective 校准；本 PR 是历史 CPU 诊断与未执行的本地留出设计，
  不是已完成的 GPU 前向验证。
- **新增材料**：量化域不匹配与绝对量级／增长形态的差异，提出待检验假设，并保留 Step 2 的原始冻结。

## 4. 模型内分量：短上下文下 `linear` 占比高，名义响应较平

在代表上下文 ctx=265、11-11 显式课程参数下的名义分量（ms）：

| B | 总计 | linear | embedding+output | misc | framework | attention |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 14.327 | 12.614 | 1.345 | 0.222 | 0.005 | 0.141 |
| 4 | 14.551 | 12.619 | 1.347 | 0.233 | 0.005 | 0.347 |
| 8 | 14.850 | 12.626 | 1.349 | 0.249 | 0.005 | 0.622 |

- `linear` 名义项约 **12.6 ms，占模型步长 ~88%，且随批大小几乎不变**；其权重流量采用每步只读一次的理想复用假设。
- `attention` 名义项 B=1→8 为 0.141→0.622 ms（约4.4倍，增加0.481 ms）；表中总计增加0.523 ms。
- 这说明该参数化下名义宏的批大小响应较平。88% 是模型内分解，不是 profiler 测得的 GEMM 占比；
  它本身不能证明真实 GPU 受权重搬运支配，也不能排除其它成本模型或调度项对闭环增长的解释。

## 5. 带宽代理与 β 假设：不能替代独立测量

原模型按 Qwen3-4B BF16 参数几何折算权重约 8.04 GB（≈4.02B 参数 × 2B）。以下保留原算式：

- 模型 C1：内存受限分量合计 ≈ 14.18 ms → 有效带宽 ≈ 8.04 GB / 14.18 ms ≈ **567 GB/s ≈ 峰值 640 GB/s 的 89%**。
- 实测 C1 = 21.20 ms：若不扣固定开销 → ≈ 379 GB/s ≈ **59% 峰值**；若扣 graph 域 `runtime_fixed`≈4.7 ms →
  ≈ 487 GB/s ≈ **76% 峰值**。

**59–76% 是把权重字节除以闭环 TPOT 得到的代理区间，不是独立 GEMM/HBM 带宽测量。**
上端还假设扣除另一个 Graph 配置域的经验截距，仅用于反事实分析，不能视为合法 eager 校准。
课程 β=0.9054 从 LN/Softmax primitive 迁移后是否高估该域成本效率，是一个待独立验证的假设。
原 TPOT 0/39 达标的阴性结果与持续 Decode 成本偏差保留，但这些除法无法确认 β 或 GPU 带宽是唯一主因。

## 6. 对当时 Step 2 设计的含义

截至2026-11-16，本分析所用材料不足以识别 eager 短上下文场景的两件事：

1. **eager 每步固定截距**：11-16 的 `runtime_fixed`≈4.7 ms 是 Graph配置域、ctx=1024 的值，不能直接搬到 eager ctx≈256。
2. **短上下文成本随批大小的变化**：原名义模型在 ctx≈256 的 `linear` 占比高、响应较平；
   需要独立分段计时与实际batch轨迹来检验KV、发射和混批等候选解释，仅闭环TPOT不能分别识别它们。

当时因此提出 Step 2：在 9070XT 上对三个 cohort 的 C1/2/4 先冻结再测量，每点3次 fresh 重复。
baseline 是重测；short/long 的低并发配置相对旧分布留出新增。原 27 × 1000 合同没有执行，
其 `[1,2,4]` 与旧 short/long `[8,16,32]` 不相交，不等于与全部旧 baseline 配置不相交。
当前若再研究，应另立新协议和独立数据；不能把已观察的 PR #13 配置重新称为未见盲点。
