# 1.10 小消息 P2P 真机独立留出记录

日期：2026-11-04。新模型显著改善了这组独立测量的**逐尺寸均值预测**，
但没有消除小消息的单次双峰波动；逐次误差目标仍未达到。

## 测量范围

同一台机器上的 RX7900XTX/gfx1100 → RX9070XT/gfx1201，BF16、TP1×PP2、
无其他 GPU 工作负载。两方向直接 peer 访问均不可用，明确设置
`NCCL_P2P_DISABLE=1`、`NCCL_PROTO=Simple`、`TORCH_NCCL_BLOCKING_WAIT=0`。
实际栈为 Python3.14.8、PyTorch2.13.0+rocm10.1.0、HIP build7.16.26385、
RCCL2.30.7；模型目标沿用 Qwen3-1.7B 的有效 PP 端点配置。
这是独立 primitive 服务测量，没有在采样时执行模型。

计时仍为预分配后的本地主机派发至 Work 完成和设备同步，取完整参与 rank
的最大值；CPU barrier、预热、分配与正确性检查在计时外。所有慢样本保留。
真实加载的 RCCL 库 SHA256：
`77d5f37cc04837d93094a1c93487ec1c2ddbb294f8c94e3392a8e469af08b0cb`。

六组分阶段诊断比较了 eager/lazy 初始化、blocking wait 开关和尺寸顺序。
lazy、blocking wait=0、逆序和打乱顺序均未消除 4KB 慢路径；约 1ms 额外时间
主要位于接收端设备完成同步。blocking wait=1 则使多个尺寸的 Work.wait
本身增加约 1ms。这些对照只定位了观察到的计时阶段，未证明更底层的 GPU/RCCL
根因。正式采样采用显式 v2 lazy 协议，与旧 v1 数据隔离。

## 冻结与独立性

四个全新训练会话使用不同固定 seed 的尺寸顺序，共 19,080 条观测、32 个尺寸，
覆盖 256B–16MiB。前两组每尺寸 60 次，后两组每尺寸 240 次。
发现训练中的波动后，只用训练数据扩充重复数，并增加 4098B 锚点；未读取留出。
每个尺寸另有 20 次真正预热。

Lookup 规则预先固定：每尺寸至少 5 次，邻接尺寸比不超过 4；绝对均值差至少
0.05ms 且超过规定的 2 倍跳变判据时阻断区间。拟合不裁剪样本、不减去同步耗时，
保持非单调曲线，拒绝所有外推。训练得到唯一阻断边为 4096B–4098B，两个端点
均可精确查询；BF16 没有位于其内部的完整元素尺寸。

两份 Profile 于 **11:09:55 UTC** 冻结；独立留出于 **11:10:40 UTC** 才启动，
启动前验证输出目录不存在及源文件 SHA。留出为新进程/新 communicator/session，
31 个尺寸各 300 次，共 9,300 条，30 个尺寸未参加训练，另有 4096B 独立重复。
训练与留出的 record/group ID 无交叉，协议、实际栈和通信环境 SHA 一致。

冻结的文件 SHA256：

- Lookup：`e98440db582e2344064bdc239eb344348993b4b33b4dad521ad4cf63c069f0ac`
- Affine：`591f54ba848b9c9eb1d99ca05ba2b582a66a2159ddd4153c41bd5b565a30cd32`
- 独立留出数据：`1281ca756c652993d86449fe2064a2c2b1b1a23d7ff9b6520fdccb47f661f8a3`

## 同域对照结果

两种方法使用**完全相同的训练数据和独立留出数据**。均值指标对每个
placement/尺寸等权，逐次指标覆盖全部观测；本次各尺寸重复数相同。
正确性错误为 0，没有拒绝、删失或被丢弃的慢样本。

| 留出指标 | Affine | Size lookup |
| --- | ---: | ---: |
| 覆盖率 | 9,300/9,300，100% | 9,300/9,300，100% |
| 逐尺寸均值 MAPE | 100.3340% | **4.8772%** |
| 逐尺寸均值 MAE | 0.279193ms | **0.029383ms** |
| 逐次 MAPE | 120.0551% | **60.2526%** |
| 逐次 MAE | 0.328049ms | **0.146322ms** |
| ≤64KiB 均值 MAPE（23 个尺寸） | 109.8877% | **5.7405%** |
| ≤64KiB 逐次 MAPE（6,900 次） | 134.8034% | **78.7379%** |

预先设定的覆盖率 ≥95%、均值 MAPE ≤10% 达到；逐次 MAPE ≤15% 目标未达到。
保留 `hardware_validated=false`，不授予整体硬件 PASS。
旧 v1 宽网格的 101.52% 是历史结果，协议和网格不同，不能代替本表的同域基线。

4KB 训练均值为 0.763162ms，p10/p90 为 0.126531/1.122016ms，
标准差 0.451564ms；4098B 均值为 0.146736ms。
4KB 以下单次快慢模式及会话间比例变化仍限制标量均值模型；例如 768B 的
留出均值误差为 26.56%，良好的总体均值误差不表示每个尺寸均达标。

## 兼容性与边界

旧 affine/v1 默认契约保留。CPU 回归覆盖 TP/PP 双张量每边界只计费一次、
receiver AllGather、缺失/阻断域在 KV 提交前失败，以及多副本阶段/通信/Workspace
三 Profile 与 Prefix Cache、chunking、swap、混合批处理的完整生命周期。
新实测 Profile 也完成 TP1×PP2 原生双张量预测接入；每个 4KB 张量计费
0.763162ms，边界共 1.526324ms。阶段分析参数不构成新的整模型精度证明。

本轮只有一个有向物理 pair；未新增反向、不同精度、多机、共享 fabric 争用或
receiver AllGather 的独立精度验收，没有四卡 TP2×PP2 实测。
独立服务也不覆盖 vLLM 元数据、上游等待、分配、计算重叠或在线 SLA。
完整 Workspace、真实 OOM 拐点和广域在线预测有效性仍遵守既有证据限制。

原始 rank 证据、失败对照、源码快照、冻结清单、全部 Profile 与逐次结果仅保存在
独立验证目录。仓库分发手算 fixture 与本脱敏报告，未加入密钥、连接地址或原始日志。
测试结束后自有容器已停止，两卡使用率为 0 且没有 KFD 进程；共享模型保持只读。
